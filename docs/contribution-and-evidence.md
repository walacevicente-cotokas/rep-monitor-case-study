## Experience represented
This portfolio reflects technical participation and hands-on work across:
- Requirements and workflow improvement for field technicians and supervisors

- Technical documentation, issue diagnosis and iterative rollout

## Claim boundaries
- This document **does not assert sole ownership or authorship of all production code**.
- Proprietary application repositories remain private; the public examples are independently written illustrations.
- Production use or deployment of any specific feature should be corroborated with release history, approved demonstrations and professional references.
- No metrics of cost savings, uptime, latency improvement, fleet size or customer count are claimed without an approved, attributable source.
- Mobile iOS release is not listed as shipped; a future plan is not equivalent to production experience.

## Talking points for interviews

**System design:** Explain why the architecture separates data collection, storage, API and frontend experiences.

**Data engineering:** Walk through a mismatch between ERP and monitoring identifiers, what can fail, and why an import review step matters.

**Performance:** Describe the trade-off behind limiting map markers instead of showing the full fleet.

**Security:** Explain server-side role checks, password hashes, session invalidation and account revocation.

**Operations:** Describe how deployment, scheduled jobs and connectivity to an on-premises database affect reliability.
